# V1 架构

应用端负责自然语言任务结构化、逐块语义分析、人物证据、候选评分、调用图像工具与对话审阅；本地包承担确定性处理。脚本不会把基于引号的候选发现冒充模型语义分析。

当前模块：storage 原子落盘/流式哈希/路径边界；ingest TXT/EPUB→规范正文/章节/段落/窗口；bootstrap 导入检查点与原子目录发布；source 将缓存索引重新绑定到原文件；quotes 候选发现/定位/改写策略；analysis 应用端语义提案；workflow SQLite 依赖/资产/调用预算；documents 多文档事务；images 调用预留/结果对账/图片来源/卡片绑定；layout 六样式；rendering 增量合成；review 离线审核及人工记录；export 审核门禁及打包；status 观察进度和失效；cli 交换入口。

应用端读 chunks.json 对各窗口语义处理，回填人物/候选与依据，再由本地核验。每条引语的 source_hash 与 canonical_hash 都锁定版本；规范正文 Unicode 码点坐标不能当作 EPUB 原始字节偏移。EPUB 用 spine 阅读顺序、正文 XML 文本提取与成员位置映射，不执行脚本、不解压到文件系统。

长文本覆盖分三层：索引范围并集、应用端实际处理窗口记录、人工语义抽查。ingest 只完成索引，semantic_chunks_processed 初始为 0；apply-analysis 验证窗口哈希和实际应用端提案后更新处理状态，增量提交保留其他已处理窗口。不会根据机械候选数宣传全文语义完成，也不会将提案中的哈希当作语义正确的证明。

审阅对象与资产哈希绑定，更新依赖必须失效。图像用本地持久文件导入，记录真实工具来源；原始小说不进入生成提示词。字体由用户本地提供，记录文件哈希与许可，不分发 Windows 字体。

## 持久化与恢复

book.json/source.ext 是来源锚点。分析、审核和卡片更新的 before/after 保存在私有 .state/transactions/；pending-documents.json 是可重放提交指针。SQLite 写锁串行化协作命令，异常退出由系统释放锁；下一次操作先恢复未物化完成的事务。documents-head.json 保留已完成写入的持久头，若文件完成后 SQLite 事件提交丢失，能补记事件而不覆盖后续人工编辑。

rendering 的输入签名覆盖原文版本、引语、人物档案及参考图、卡片参数、字体、底图、依赖版本与渲染代码。产物以 card_id+签名生成版本路径；完整图/报告/预览均匹配时复用。中断或损坏不会覆盖原资产；完成图像与回填卡片之间的中断可恢复为复用。排序不进入单卡签名，导出仍按当前 cards 顺序编排。

审核页为自包含本地 HTML，小说文本通过 textContent 展示，嵌入 JSON 转义脚本终止符，不发网络请求。下载记录不自动应用；apply-review 验证整份记录后事务提交。人工记录是操作者声明，不是身份认证；AI 测试数据与真实批准严格区分。任何来源/档案/文字/排版依赖变化使旧版本审核无法用于正式导出。

bootstrap 在同级 .ingest-staging/ 保留原文件、配置、代码版本和逐阶段检查点，完成后才把完整目录发布到用户指定的 run。显式 --resume 复用哈希匹配的阶段，损坏阶段隔离重算。完成后的原文件/索引/契约固定，后续分析与审核属于可版本更新资料，不会被重复导入覆盖。

images 的预留命令不发网络请求，只给应用端一次执行许可或要求先对账。已确定结果不能被改写；未知结果找到实际文件后，可在原调用名额内注册成功。图片按内容保存，登记记录绑定收据、人物、实际输入和调用；正式导出不接受单独一项 image_kind 声明。user_provided 图片与生成图分开，不占生图预算、不计入生成数。预算 schema 2 增量保存请求/结果，不重置旧上限和调用。

bundles 按字段白名单构造可移植交付摘要，固定 ZIP 元数据并核对逐文件库存、图像和交叉引用；独立验证不认证原句或审核身份。export 以输入快照绑定顺序、人物、审核、图像及制作代码，在同级 .export-staging/ 保存尝试、验证完整包，再次核对当前输入后原子发布目录。--resume 只复用匹配且完整的包；运行内 .state/exports/ 保留导出历史，丢失的发布事件可补记。旧包不因当前输入修改而被覆盖，但 status 会报告失效。

审核标签按同名人物的区别别名显示；说话人审核签名也绑定姓名及别名。dialogue_cases 提供四章自写困难对白与应用端处理提案，作者预期只用于回归，不是外部人工金标准。

review_policy 固定视觉审核版本与五项人工判断。视觉政策 2 的审核页嵌入完整图、校验后的手机图、可用基准图和居中正方形模拟裁切，记录各视图哈希和裁切范围；原尺寸弹窗不受页面图片缩放限制。apply-review 核对视图和政策，全部判断通过后才允许批准干净候选；export 再查逐项记录，旧政策审核不继承。生成卡片的基准图须有非测试来源登记，基准收据也参与渲染依赖核对。人物一致性与可读性仍是人的判断，哈希不证明画面质量。render_inputs 拒绝说话人/卡片人物冲突和未确定归属，避免更正提案后继续生成误署名图片。

edits 以完整文档快照绑定显示文字/卡片绑定/风格/顺序操作，先在副本上验证整批，再用 documents 的 expected 比较在同一 SQLite 写锁内提交。请求身份关联不可覆盖的计划和事务 reason，已提交但返回丢失时可恢复结果；已发生后续修改则拒绝旧重试。quote_exact 和 source 不可通过该接口变更，换人物移除旧配图指针，旧字节和 before/after 保留。排序保留单卡产物，使历史导出和整组审核输入失效。

albums 将书名/来源、首图政策、精确顺序和各张审核签名/图像哈希组成整组目标。schema 3 审核页增加顺序缩略图和四项整组判断，决定写入独立 album-review.json，与单卡审核一起事务提交；提交时比较全部原依赖，避免审核导入覆盖并发修改。正式 export 缺少当前整组批准即拒绝，导出快照也包含整组声明。包清单 schema 3 附带字段白名单裁出的整组记录，独立 verifier 检查其与图片清单相同；旧 schema 2 仍可做原完整性检查，不新增旧包的审核结论。所有身份/视觉记录仍为人的声明，不由哈希认证。

contracts 以版本化 task-contract.json 保存独立任务意图，不从已有卡片推断数量。选择约束进入准备、审核及正式导出；契约指纹进入单卡/整组批准与工具请求，旧记录保留而新要求重审，不因策略变动自动重排或生图。契约更新与调用预留共享 SQLite 写锁，提交 guard 在锁内复查保守占用，不重置预算。预留前比较契约/人物版本，未知旧调用仍经原收据对账。preparation-report 保存缺口；包 schema 4 带可移植任务记录，验证仅核对声明的选择范围，旧 2/3 包不回填契约。主题与禁用元素显示为待人判断的要求。

prepare-cards --append 根据契约填缺口，计数器与卡片进入同一恢复事务；旧运行初始化时扫描已保留的卡片历史 ID，正常续加使用单调计数器。原卡片对象和资产保持不变，新增卡片使整组签名变化。新增数/reused/事务位置是本次操作结果，preparation-report 保存当前总量和缺口。

apply_analysis_file 固定一次读取的原始字节、保留显示编辑和实际参考链接，再按依赖快照提交。图片注册/绑定、基准设置及渲染指针也比较原版本；并发更新通过拒绝陈旧写入保留，而非覆盖。真实双连接测试验证同一旧快照只能有一份提交，其余重读后重试，不自动重生图片。渲染后复查输入文件，检测到中途变化的结果不写 tracked 指纹，失败资产保留；正常重试可复用完整、有效但尚未回填的渲染。

上述恢复主要证明确定性文件链路。预留/记录失败已通过真实内置调用复核，结果仍为 HTTP 404；成功生图、参考编辑和产物交接尚未实测。模拟注册中断不证明外部调用 exactly-once。

任务定义 schema 2 的调用分配按已有结构化请求重算占用，不增第二套可漂移计数器；总额度、分项额度、重试关系及输入快照在同一 SQLite 写锁内检查后预留。修订契约与批准记录提交也在该锁内复查预算，拒绝并发旧记录导致的超项批准。新图像请求快照 schema 2 明确新候选消耗 alternative；旧 schema 1 的自由文本原因不重解释为审美用途，未知用途保留 unclassified。契约/请求版本更新不重写旧调用或结果；输入未变的旧操作返回原预留对账。独立包校验仍只核对选择声明，不把无运行台账的包当预算执行证明。

source_context 为语义审核政策 1 构造可验证完整段落：按段落坐标二分查找原句/证据，取同章相邻段，排序合并重叠区域；跨章不合并，间隔显式保留。段落原文和指纹不改写 quote_exact/source。离线页单独嵌入相关整章供查看，整章不下载进审核记录；成品包只携带政策版本和审核上下文指纹，沿用原有证据白名单。原句审核指纹包含上下文政策版本，正式批准比较实际材料，导出/状态重算所需上下文；旧记录保留而不自动升级。人仍负责归属真值。bootstrap 允许从零图像额度建立本地任务，负数/非整数拒绝。
